# Handover: decision speed + decision quality (branch `feat/laya-decision-speed`)

What was built, how to check it, and how to fly it yourself. Full numbers: [LAYA-DECISION-SPEED-RESULTS.md](LAYA-DECISION-SPEED-RESULTS.md).

**Plug the laptop into AC before any sim test.** On battery, AirSim stalls and survey routes abort on stale state
(seen on 2026-11-06 11:00-11:30).

## What changed

| Area | Change | Where |
|---|---|---|
| Speed | Tool catalogue fixed per session, so every decision reuses the prompt cache; unknown `target_id`s rejected by the validator instead of an enum | `python/dcm/agent_tools.py` (`decision_tools`, `validate_call`, `known_target_ids`) |
| Speed | Warm-up sends the real catalogue, so the first decision is cached | `python/dcm/llama_runtime.py` (`warm`), `python/dcm/fly.py` (`prepare_runtime`) |
| Speed | Camera questions answered by the already-loaded Qwen3.5-4B (projector `--mmproj`), no model unload/reload | `llama_runtime.py` (`ResidentVision`), `python/perception/vlm.py`, `scripts/autonomy/run_mission.py` (`_vision_lease`) |
| Speed | Projector moves to the CPU only when it would push model layers off the GPU (AirSim); that server runs at nice 10 with a 256-image-token cap | `llama_runtime.py` (`_projector_displaced_layers`, `CPU_PROJECTOR_NICE`) |
| Quality | `finish(completed)` is checked once against tool receipts; unresolved failures are sent back to the model | `fly.py` (`unresolved_failures`) |
| Quality | `VIEWPOINT_REQUIRED` no longer invites invented motion; `search_for_object` says it cannot count; counting rule covers "the surroundings" | `agent_tools.py`, `config/dcm/prompts/system.md` |
| Flight stack | LOCAL_POSITION_NED requested at 20 Hz (was 5 Hz) against the 500 ms staleness limit | `cpp/mavlink_gateway/mavlink_gateway.cpp` |
| Config | Projector path + sha256 in the runtime manifest | `config/dcm/agent-runtime.json` |

## What to look for

- **Speed.** The final line prints model decisions; per-decision latency for any run:

  ```bash
  .venv/bin/python scripts/autonomy/episode_latency.py logs/episodes/<episode-id>
  ```

  Expect a median decision of ~2 s. Last night's medians were 2.0-3.8 s; before this branch it was 14.9 s. Camera questions should take ~1-2.5 s, and the model must not reload between them: the `llama-server` PID stays the same during a mission.
- **Projector placement.** In AirSim, `ps -o ni,args -C llama-server` should show `NI 10` and `--no-mmproj-offload`
  (projector on CPU). In Gazebo there should be no `--no-mmproj-offload` (everything fits on the GPU).
- **Honest outcomes.** If a step fails and isn't redone, the summary should say `incomplete`. A line
  `Finish check: completed claimed with unresolved ...` means the model claimed success over a failure and was sent
  back. That's expected; the outcome printed after it is what counts.
- **No invented motion.** After a `VIEWPOINT_REQUIRED` result, the next move should be a turn/search, `ask_user`, or
  `finish`. A forward/sideways `move_relative` you never asked for would be a regression.
- **Episode records** live in `logs/episodes/<id>/events.jsonl` (each `agent_decision` has `stats.tokens_cached` /
  `tokens_prefilled`; a cache hit means almost all prompt tokens are cached).

## Known open issues

- "Take a look around" checks only the forward view (there's no turn-and-describe tool in the live catalogue).
- A failed survey route is sometimes followed by going home instead of one retry.
- Hedged VLM answers ("possible structure") count as found; the LiDAR gate blocks acting on them.
- Codex's mission in AirSim can end `incomplete` when the planner finds no collision-free climb beside the building
  (1 of 2 runs on 2026-11-06).
