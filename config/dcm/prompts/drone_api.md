# DRONE_API.md
Native tool schemas define calls and arguments; return a tool call, never prose code. Units: metres, m/s, seconds, degrees. Coordinate destinations declare home_relative_ned or local_ned (with origin_id); altitude_agl_m is above HOME, not terrain. view accepts a compass name, absolute degrees, or current; the adapter resolves measured yaw. face_heading and directional observations turn the aircraft horizontally; yaw is a relative signed turn. Body-relative forward/right follows current heading.

Use user-supplied/measured coordinates or registered geometry. Missing named waypoints need clarification; camera pose is not object position. goto/approach_target/orbit require a typed destination containing its geometry and arrival values: object standoff, coordinate altitude, or coordinate-orbit radius. Native schemas specify each variant; do not mix its fields with other reference types. Visible objects supply appearance and view; the controller faces that direction and localizes before object-relative movement. goto addresses coordinates or saved poses; approach_target selects object surface standoff; overfly_target measures and flies above a visible/registered object; object orbit uses surface standoff. Coordinate flight and named waypoints remain distinct. Preserve explicit values; unspecified operating values use context.defaults.

The adapter supplies identity, lease, timestamps and origin, dispatches ActionService (proto/icarus/v1/drone_api.proto), and waits for a terminal result. ACCEPTED is not success. Short execute_sequence groups stop at failure and cannot cross observations/decisions. Routes/patterns delegate geometry and flight to ArduPilot.

Home/launch orbit references resolve from measured state. Select camera for visual intent, or none for heading-only flight. Nose-facing yaw cannot tilt a fixed camera; geometric feasibility and actual image evidence are separate. Object standoff is minimum distance from the observed hull, with reported tracking reserve; it is neither center radius nor global obstacle clearance. Unseen geometry stays unknown.

Use scan_heading for turn-observe cycles and scan_area for sampled flight observations. Scans own turn/path–settle–observe cycles. Select exit_policy: finish_at_match ends a detector search at its first matching station; pause_at_match allows resuming after a nested branch; each_observation yields for arbitrary decisions; complete_coverage runs an unconditional bounded scan. Match policies require stop_on_detection and optional minimum_count. A failed observation remains pending. A paused next station is optional, not an obligation to continue after the user's condition is satisfied. Report measured sweep/waypoint progress: workflow completion at a match does not imply completed coverage. An unmatched sweep does not finish an open-ended search; sampled views do not establish complete visual coverage.

Older or large observation details stay in retained action results. Follow their action index/path with read_action_result when needed; lookup success is not flight success or fresh observation.

context.registered_waypoints initially supplies a catalogue index; get_context(include_waypoints=true) loads callable pose references for this mission; use each entry's destination. The adapter retains the complete position and heading, rather than asking the model to reconstruct a pose. Optional named waypoints come from ICARUS_WAYPOINTS_FILE: a JSON catalogue with coordinate_frame="home_relative_ned" and entries containing name, north_m, east_m, and optional altitude_agl_m and heading_deg. Unknown names require coordinates; camera poses do not create waypoints.

Catalogue role identifies navigation_pose (default), observation_pose, or explicitly supplied orbit_center. Navigation/observation poses do not identify physical object centers or overhead positions. Orbit centers may include target_altitude_agl_m for camera geometry. A confirmed fresh landed-and-disarmed state already satisfies land; never arm to repair an already completed landing.

The takeoff tool is phase-aware: from landed it arms and departs; while airborne it reaches the requested altitude above home while holding horizontal position. It never re-arms in flight. An explicit departure climb rate is not silently applied to an airborne goto.

For inspect_scene select question_type: condition for a yes/no visual decision (false is valid, null is unknown), description for appearance or scene details (unanswerable is unfinished). A camera capture alone does not establish the requested description.
