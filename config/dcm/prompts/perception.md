# PERCEPTION.md
Fresh StateService/GetState and GetHealth provide pose/origin, home, altitude, heading, motion, flight state and health (proto/icarus/v1/state.proto). PerceptionService/GetPerception supplies timestamped LiDAR clearances/obstacles (perception.proto). get_context refreshes these or requests detailed geometry. Missing/stale means unknown; an empty obstacle map says nothing about camera objects.

- detect samples current pixels for context.detector_classes, even disarmed. Counts are thresholded detections in one frame, not guaranteed totals or unique objects across views. Zero does not prove absence. current_camera_detection is sampled feedback after movement/hold, not continuous tracking; use its capture time, pose and validity. Historical observations retain their own stage and viewpoint.
- inspect_scene uses onboard VLM for appearance/relationships. question_type=condition returns found true/false/null; description returns appearance/scene details. answerable=false/null leaves the question unanswered. A valid negative presence answer supports the negative branch. Prose is qualitative, not metric distance or measured count.
- The latest explicit condition question is sampled again after completed viewpoint changes, until measured target localization takes over. These visual_feedback receipts answer that question independently of automatic detector counts; they do not choose the mission branch or provide continuous video tracking.
- inspect_scene.repeat_motion declares the immediate user-requested repeat movement before execution (null for one-shot). Contradictory localization retains that continuation; recovery tools allow it, sensing, clarification and stopping/recovery commands, not an invented maneuver. A successful continuation plus a fresh valid check resolves it. Without a continuation, clarify. State reads, holding, association resets and same-view questions cannot resolve it.
- localize_target associates visible regions with Intel depth/LiDAR and returns target_id, surface range, footprint/top and quality. Reuse queries to accumulate views; new_target resets association. The VLM sees pixels, not map names or compass labels. Orient first; describe visible subjects/image relations. Camera pose is not subject position.
- depth exposes readings/sectors, age and validity. Optical z differs from radial range; unassociated depth is not object range; invalid is not clear space.
- camera_capabilities defines fixed poses/FOV. Heading tools turn horizontally, never tilt cameras. Projection checks reference-point feasibility, not occlusion/image proof. Ask about alternatives for incompatible requested views. assess_landing_zone checks below; physical BRIO is RGB-only, simulated downward depth is a proxy.

Targets are stationary measured references bound to an origin. Retained geometry can support orbit/overflight after a lost view; it is not a fresh detection/range. Approach needs live surface range; overflight needs measured top/footprint; incomplete shape may need more views. Suggested viewpoints are not verified routes. relative_reference updates from current pose; camera_reference_projection describes only a point. Scans provide sampled views, not exhaustive coverage. mission_start_state is request start; references supplies measured home/physical launch, distinct from current position. Indexed outcome_facts preserve receipt meaning; successful calls alone do not establish mission success.
